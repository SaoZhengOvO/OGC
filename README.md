## 一、项目背景与赛题概述

本项目针对“动感地带 AI+ 高校创智计划”AI 技术赛道之**赛题二：数字人综合情感陪伴对话模型**。

赛题聚焦数字人情感陪伴与智能对话场景，要求模型具备**情感理解、记忆融合、共情表达、用户画像推断**等核心能力，提升在多场景、多轮对话中的自然度、连贯性与情感支持力。

### 参赛核心规则
- **提交形式**：Docker 镜像离线自动化测评。
- **环境特性**：**完全离线禁网环境**（严禁且无法调用任何公网 API，必须全量集成模型权重与推理引擎）。
- **评测机会**：初赛阶段最多仅有 **5 次成功评测机会**，成绩以**最后一次成功提交**计入最终排名；容器报错/运行失败不占用测试机会。

## 三、总体技术架构方案

为了兼顾**高分类准确率**、**高文本重合度/语义相似度**与**极低端到端时延**，推荐采用 **端到端多任务结构化微调（Multi-Task Instruction SFT）** 作为核心架构：

```
           ┌──────────────────────────────────────────────┐
           │        输入：多轮对话上下文 (Dialogue Context) │
           │        + 候选枚举空间约束 (Label Constrained)   │
           └──────────────────────┬───────────────────────┘
                                  ▼
           ┌──────────────────────────────────────────────┐
           │     基座模型：Qwen2.5-7B-Instruct (4-bit/BF16)│
           │     微调机制：LoRA / SFT + DPO 共情对齐        │
           │     加速推理：vLLM 高性能批处理推理引擎        │
           └──────────────────────┬───────────────────────┘
                                  ▼
               ┌──────────────────┴──────────────────┐
               │ 一次前向推理输出标准化结构化 JSON (低时延) │
               └──────────────────┬──────────────────┘
                                  ▼
    ┌─────────────────────────────┼─────────────────────────────┐
    ▼                             ▼                             ▼
【情感识别】(25分)          【用户画像推断】(15分)       【共情回应生成】(20分)
- 闭集标签强制匹配          - 属性维度键值抽取           - 契合 Ground Truth 风格
- 规则兜底校验保证格式      - 历史记忆融合推断           - 兼顾 BLEU-4 与 BERTScore
```

### 1. 基座选型
- **首选**：`Qwen2.5-7B-Instruct`
  - 中文语义理解、多轮对话与 JSON 结构化遵循能力顶尖。
  - 显存适中（单卡 24G 轻松吞吐，量化后仅需 6~8G 显存）。
- **备选**：`InternLM2.5-7B-Chat` 或 `GLM-4-9B-Chat`。

### 2. 核心技术模块
1. **多任务联合优化**：单次推理同时输出：
   - `emotion`: 情感分类预测（计算 Acc）
   - `user_profile`: 画像属性字典（计算 Acc）
   - `response`: 最终共情文本（计算 BLEU / ROUGE / BERTScore）
2. **受限解码与规则兜底（Constrained Decoding）**：
   - 使用固定 JSON Schema，杜绝大模型臆造分类标签。
   - 增加后处理映射字典，确保即使小幅拼写偏离也能精确归一化到官方标签空间。
3. **推理加速引擎（确保 10 分满分）**：
   - 部署 `vLLM` 框架，开启 PagedAttention 与连续批处理（Continuous Batching）；
   - 设置合理的 `max_new_tokens`，避免冗长回复拉低时延评分。

## 六、关键约束与避坑指南

1. **绝对禁网（No Internet Access）**：
   - 评测容器完全物理隔离，**不得调用任何外部 API**；
   - 依赖包必须预先 `pip install` 装入镜像，权重文件必须固化在镜像或指定挂载卷中，严禁在代码中出现 `huggingface_hub.download` 或 `requests.post`。
2. **提测次数限制（最多 5 次成功机会）**：
   - 容器运行崩溃（Exit code != 0）不扣除次数；
   - 只有成功输出预测结果才计入 1 次；
   - **最终成绩只认最后一次**！切忌在第 5 次盲目做不稳定的大规模改动。
3. **平台运行记录（10分硬指标）**：
   - 必须在咪咕仝学平台留下充足、可信的实例运行、微调训练日志。
4. **输出格式严格校验**：
   - 自动化评分脚本通过比对 JSON 字段自动打分，字段名若拼错（例如 `emotion` 写成 `emotions`）将直接导致对应项 0 分。
   - 入口脚本必须加入 Pydantic / 字典类型校验。

## 七、环境依赖与快速启动指引

### 1. 本地开发环境要求
- Python 3.10+
- PyTorch 2.1.2+ (CUDA 11.8 / 12.1)
- 显卡推荐：NVIDIA RTX 4090 (24GB) 或更高级别 GPU

### 2. 本地自测命令
```bash
# 1. 安装核心依赖
pip install -r requirements.txt

# 2. 本地离线全流程自检 (模拟评测容器执行)
bash run_all.sh --input_path ./data/sample_test.json --output_path ./output/prediction.json

# 3. 计算本地自测得分
python src/evaluate.py --ground_truth ./data/sample_test.json --prediction ./output/prediction.json
```
