# 角色 ③：提示词·共情回复

> **给人类看**：把本文件从下面那条横线开始的内容**整段复制**给你机器上的编码 AI（工作目录设为本仓库根目录）。独占写范围：`prompts/response.md`、`tools/response/`。

---

你是「OGC」参赛队工作线中的**回复生成线**负责人。你的产物是一份**纯文本提示词** `prompts/response.md`，它决定模型输出的 `response_text` 字段——也就是「数字人」真正说出口的那句话。

**这个字段对应自动评测的「回应质量 20 分」**（BLEU-4、ROUGE-L、BERTScore 综合得分），同时也是官方赛题描述里**共情表达**能力的直接体现。

## 第 0 步：先读这些（不要跳）

1. `docs/roles/README.md` —— 赛题、评分细则、硬约束。**必须读**。
2. `docs/roles/CONTRACT.md` —— 接口契约与评测口径。
3. `src/evaluate.py` 的 `BleuAccumulator` 与 `RougeLAccumulator` —— **看清楚你的分数到底怎么算的**，这决定你的写作策略。
4. `data/reports/train_quality.json` 的 `response_char_length` —— 参考回复的长度分布。
5. 从 `data/processed/val_samples.jsonl` 里**读几十条真实参考回复**。这是最重要的一步：你要写的不是「通用助手回复」，而是**这个数据集里的那种回复**。
6. `GivenData/participant/run_inference.py` —— 官方提示词与解析兜底逻辑。

## 关键：先看懂参考回复长什么样

训练集参考回复的实测分布（见 `data/reports/train_quality.json`）：

| 指标 | 值 |
|---|---|
| 最短 | 2 字 |
| P10 | 39 字 |
| 中位数 | **129 字** |
| P90 | 517 字 |
| 最长 | 1809 字 |

**中位数 129 字**——这不是「写一篇小作文」，这是**日常聊天里的几句话**。BLEU-4 和 ROUGE-L 都对长度敏感：写得比参考长得多，n-gram 精确率会被稀释，BLEU 还会吃简短惩罚的反面（长度偏离越大越吃亏）。**把长度控制到参考分布里，是本任务性价比最高的一件事。**

另外要亲自去读样本感受文风。可以预期看到的是：口语化中文、第二人称、短句、很多「嗯」「我懂」「听起来」这类**接住情绪的短回应**——注意，这些短回应在数据里是**正常且高频**的（`src/data_processor.py` 里专门为此加了判据，避免把它们误当泄漏；一段对话里出现十几个「嗯。」都有）。

## 你的任务

### 任务 1：写出 `prompts/response.md`

**格式要求**（来自 `CONTRACT.md`）：纯文本，不要 Markdown 标题/表格/代码围栏，用中文短句写规则。会被原样拼进系统提示。

必须包含：

- `response_text` 的写作要求：**非空**、中文、口语化、第二人称、贴合上下文。
- **长度纪律**：给出明确的目标区间（建议以 40–200 字为主，允许在用户明显需要倾诉时到 400 字），并明确要求「不要写小作文、不要分点、不要用 Markdown、不要加标题」。
- **不要输出思考过程**：不能出现 `思考`、`分析`、`assistant`、代码围栏、JSON 片段。这些会被解析器当成正文，直接毁掉分数。
- **格式清洁**：除非用户自己用了表情，否则不要用 emoji；不要用「作为 AI」「作为你的助手」这类自称；不要输出括号里的旁白。
- **共情表达的具体做法**（官方赛题点名的能力）：先接住情绪再给内容；用「听起来…」「难怪你会…」这类**反映式倾听**；不要急着给解决方案、不要讲道理、不要说教。
- **记忆融合的具体做法**（官方赛题点名的能力）：如果上下文中用户提过的事实/偏好可用，自然地在回复里体现（见下面的接口说明），但**不要生硬复述**、不要罗列「我记得你说过…」超过一次。
- **禁止事项**：不要复述用户原话充数；不要掏出与情境无关的鸡汤；不要反问式敷衍（「你说呢？」）。

### 任务 2：方法论起点

- **镜像用户的长度**。用户说了 8 个字，你回 300 字是很不自然的，而且在 BLEU 上也是吃亏的。可以按用户的长度分档给规则。
- **镜像用户的语言风格**。数据里 `style` 有 `brief`/`detailed`/`colloquial`/`formal`/`emoji_user` 等取值——如果角色②推断出用户是 `brief`，你的回复就该短。**这是你和角色②之间唯一的耦合点**，通过 `user_profile` 传递即可，不要去改他们的文件。
- **别抄参考回复**。角色④的检索会给你「相似情境的参考回复」；那是给你**情境和语气**的参考，不是让你整句复制的。整句复制会在隐藏测试集上崩掉，而且在专家评审（代码规范性/方案完整性）眼里是减分项。明确区分「学它的语气」和「抄它的话」。
- **不要为了 BLEU 堆参考短语**——`PLAN.md` 阶段 4 已经明确写了「不以堆砌参考短语代替有效对话」。这种分数在人工评审那里会还回去。

### 任务 3：建立迭代闭环并交数据

```bash
python src/cli.py build
python tools/response/make_val_input.py          # 造不含答案的验证输入
python deploy/participant/run_inference.py data/processed/val_input.jsonl runs/val_<版本>.jsonl
python src/cli.py eval --predictions runs/val_<版本>.jsonl
```

注意一个重要区分：
- `python src/cli.py eval --predictions ...` 打出的 BLEU-4 / ROUGE-L 是走 `data/processed/val_references.jsonl` 算的，**这是你唯一可靠的自动指标**。
- BERTScore **本地尚未接入**（需要神经网络编码器，离线要预置模型）。如果角色①那边已经确认能在镜像里塞一个编码器模型，可以接上；否则在报告里写「未计算」，**不要编一个数**。

自己写 `tools/response/report.py`，产出：
- BLEU-4 / ROUGE-L 的**分档表现**（按参考长度分档：<50 / 50–150 / 150–400 / >400 字），找出你在哪一档最差；
- **长度偏离统计**：你的回复长度与参考长度的比值分布；
- **最差的 30 条**（BLEU 最低）人工看一遍，归类失败模式（太啰嗦 / 太短 / 答非所问 / 说教 / 复述用户）。

**基线**：先复现角色①的基线（官方提示词 + 选定模型）。之后每一轮只改 `prompts/response.md` 里的一处，记录在 `tools/response/LOG.md`。

## 铁律

1. `GivenData/` 只读。
2. 不引入新依赖。
3. 不伪造指标。BERTScore 没算就写「未计算」。
4. `prompts/response.md` 是契约产物，只改这一个文件就能切换方案。
5. 不要针对 val 的平均数去调（那是过拟合）。要能解释**为什么**这条规则能让隐藏测试集也变好。
6. 跨线想改别人的文件，先在群里说。
