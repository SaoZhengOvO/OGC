## 三、全队规矩（不是建议，是验收条件）

### 1. 三条命令（每天都用）

```bash
python src/cli.py build                          # 展开官方数据 → data/processed/
python tools/eval_loop.py --tag <你的实验名>      # 全量打分，自动记进 runs/leaderboard.tsv
python -m unittest discover -s tests             # 回归测试，必须全绿
```

**不要自己另算一套指标。** 五个人必须在同一份验证集上用同一个裁判，否则数没法比。

### 2. 交给别人的东西必须过三关

1. `python -m unittest discover -s tests` 全绿
2. `python tools/eval_loop.py --tag <名字>` 跑完并留了台账行
3. 没有越界动别人的目录

### 3. 服务器怎么用（`/mnt/workspace/OGC`）

**只有一台，所以要排队。**

| 规矩 | 原因 |
|---|---|
| 要跑分/训练先在群里喊一声 | 同一时间只能跑一台免费实例 |
| 长任务挂 `nohup`，别让终端窗口关掉就断 | 1 小时无操作会关机 |
| 别装 `cu130` 的 torch | 会把 ROCm 版换掉，GPU 直接废 |
| 关了就找队长重开 + 重新扫码 | 终端 URL 每次都不一样 |

**服务器上能白的干什么**（这才是不用白不用的部分）：

- 全量 2354 条的评测（本机 8 GB 跑一次要很久，服务器几分钟）
- 基座模型选型实验（8 GB 只能跑 1.5B/3B，服务器能跑 32B+）
- **如果队长决定开微调：SFT 训练**

### 4. 不许伪造

指标、日志、截图必须真跑出来；**没跑就写「未跑」**。这条同时保护专家评审那 30 分。

### 5. `GivenData/` 只读

唯一例外：角色①的 `participant/configs/inference_config.json`（那是我们自己的参赛配置）。

### 6. 不要自作主张换技术路线

要改先在群里讨论。**队长拍板前，所有人按现有路线走。**
