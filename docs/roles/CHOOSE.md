# 选线表 —— 五条线，挑一条

> 这份表是给队员挑活用的。挑完把对应提示词整段贴给你的编码 AI（工作目录 = 本仓库根目录），
> 它就知道该干什么。开工五步命令见 [`../../START-HERE.md`](../../START-HERE.md)。

## 先知道四件事

1. **不训练、不微调。** 路线是「3B 小模型 + 提示词 + RAG」。仓库里没有训练脚本，也不会有。
2. **时间很紧**，每条线都要能独立出活。接口已经在 [`CONTRACT.md`](CONTRACT.md) 冻结，**不要改别人的文件**，要改先群里说。
3. **只有一个裁判**：`python tools/eval_loop.py --tag 你的实验名`。任何改动都用它在同一份验证集上打分，结果自动进 `runs/leaderboard.tsv`。不许自己另算一套指标。
4. **官方评分怎么分**（总 100 = 自动评测 70 + 专家评审 30）：

   | 评分项 | 分值 | 归谁 |
   |---|---|---|
   | 情感识别准确性 | 25 | ② |
   | 回应质量（BLEU-4 / ROUGE-L / BERTScore） | 20 | ③ |
   | 用户画像推断 | 15 | ② |
   | 推理性能 | 10 | ① |
   | 平台运行记录 | 10 | ① |
   | 方案完整性 | 10 | ⑤ |
   | 代码规范性 | 10 | ⑤ |

   **④ 不直接计分**——它是给 ②③ 供弹药的。选 ④ 要有心理准备：你的成绩体现在别人的分数上。

## ① 部署与评测 · *守门人*

**一句话**：把模型塞进 Docker，让它在咪咕平台的 4090 上**真的能跑起来**，并且留下平台运行记录。

| | |
|---|---|
| 每天在做什么 | 写 `deploy/Dockerfile`、`deploy/entrypoint.sh`；配 `GivenData/participant/configs/inference_config.json`；本地和咪咕平台上跑 `tools/eval_loop.py`；把每次上机操作记进 `docs/platform-log/` |
| 需要什么底子 | Linux 命令行、`docker build/run` 不陌生、不怕折腾环境 |
| 难度 / 风险 | ★★★★ / **★★★★★** |
| 为什么风险最高 | 镜像跑不起来 = 全队零分。而且只有 5 次测评机会、平台卡时券只有 **10 卡时** |
| 交付物 | 可提交的镜像（≤ 50 GB）+ `performance_report.json` + 平台运行日志 |
| 第一件事 | `python tools/eval_loop.py --tag smoke --limit 20` 本地跑通 |

**这条线的人要记得**：你在本地验证过的镜像，不等于在 4090 上能跑——CUDA 版本、显存、离线依赖都得在平台上再验一遍。

## ② 提示词 · 情绪与画像 · **分值最大（40 分）**

**一句话**：让模型在**最新那条用户消息**上判准情绪（16 类）和画像三维标签（10 / 12 / 11 类）。

| | |
|---|---|
| 每天在做什么 | 改 `prompts/emotion_profile.md`；跑 `eval_loop.py` 看**情绪 Acc** 和**画像 Acc**；针对小类逐条写触发条件 |
| 需要什么底子 | 中文情绪语感好、愿意一条条看 badcase。**不需要会训练** |
| 难度 / 风险 | ★★★ / ★★★ |
| 交付物 | 一份可用的 `prompts/emotion_profile.md` + 每次改动的分数台账 |
| 第一件事 | 跑全量基线，把 16 类的 per-class 表现列出来，找出最亏的几类 |

**三条能直接换成分的判断**（已写进提示词，别丢掉）：

1. **画像宁可少写。** 画像按维度的**集合精确匹配**算，多写一个错标签会让**整个维度归零**，比留空还亏。训练集里 **36.6%** 的预测点三维全空——空白是常见正确答案。
2. **情绪有 0.34 的免费基线**：anxiety 占训练集 34%，无脑输出它就有 0.34。所以真正的工作量在**小类**（care 0.4%、surprise 0.3%），每个小类得有一条明确触发条件。
3. **画像是逐预测点的，不是对话级恒定。** 前 4000 段对话里有 1299 段对话内画像在变，其中 978 段是**非单调**（有增有减）。

## ③ 提示词 · 共情回复 · **20 分**

**一句话**：让回复像真人陪伴——长度、语气、内容都对得上。

| | |
|---|---|
| 每天在做什么 | 改 `prompts/response.md`；跑 `eval_loop.py` 看 **BLEU-4 / ROUGE-L**；读 badcase 对比参考回复 |
| 需要什么底子 | 文字功底 + 共情语感。同样**不需要会训练** |
| 难度 / 风险 | ★★★ / ★★★ |
| 交付物 | 一份可用的 `prompts/response.md` + 分数台账 |
| 第一件事 | 跑基线，随机抽 20 条对比「我们出的」和「参考回复」差在哪 |

**两条关键事实**：

- **别写小作文。** 参考回复中位数 **129 字**、P10 只有 **39 字**。BLEU/ROUGE 对长度敏感，把长度控到参考分布里是性价比最高的一件事。
- **训练集里 39 条「嗯，我听着。」式的短回应是正常的**，别为了"不重复"硬改，陪伴场景本来就该这样。

## ④ RAG · 语料与检索 · *不计分，但给 ②③ 供弹药*

**一句话**：从训练集里检索「相似处境 + 真人怎么回」，当参考喂给模型。

| | |
|---|---|
| 每天在做什么 | `rag/corpus/build.py` 建语料、`rag/retrieve.py` 写检索、`rag/memory.py` 补记忆引用 |
| 需要什么底子 | 会 Python，懂关键词/向量检索的基本套路 |
| 难度 / 风险 | ★★★★ / ★★★★ |
| 交付物 | `retrieve(sample, k=3) -> list[dict]`（签名已冻结） |
| 第一件事 | 先把语料建出来，用 3 条样例肉眼验检索结果对不对 |

**铁律**：**只读 train，绝不碰 val**。验证集不准以任何形式进语料或索引。

**降级预案**（两天做不完就果断用）：上向量检索来不及，就退到「字符 n-gram / 关键词相似度 top-k」，一样能出活。
